# MediAssist AI

A multi-agent clinical knowledge assistant. A user uploads a medical report (PDF), optionally lists their current medications, and receives a plain-language summary, a drug interaction check, relevant medical background, and a final patient-friendly explanation — generated by a pipeline of four cooperating agents.

> **Disclaimer:** This is a student portfolio project using entirely synthetic test data. It is not a medical device and does not provide medical advice. All AI-generated output is for informational purposes only and must not replace consultation with a qualified healthcare provider.

---

## How it works

A single endpoint, `/process-report`, runs an uploaded PDF through four agents in sequence:

```
PDF upload
  → text extraction (pypdf) → chunking → embeddings stored in Chroma
  → Agent 1: Report Summarizer        (LLM)
  → Agent 2: Drug Interaction Agent   (RxNorm + openFDA, no LLM)
  → Agent 3: Medical Knowledge Agent  (LLM extracts conditions → MedlinePlus lookup → Chroma)
  → Agent 4: Patient Explanation Agent (LLM)
  → JSON response: summary, drug_interactions, medical_context, final_explanation
```

**Agent 1 — Report Summarizer**
Extracts and chunks the PDF text, then asks the LLM to produce a plain-language summary that clearly flags abnormal values. Markdown artifacts are stripped from the output before it's returned.

**Agent 2 — Drug Interaction Agent**
Looks up each medication the patient enters against RxNorm (to resolve the generic name) and openFDA (to pull labeled interaction data). Scoped to prescription drugs. Includes a cross-mention check: if one medication's interaction text explicitly names another medication the patient is also taking, that's flagged and passed to Agent 4 as a required talking point — so a real risk (e.g. warfarin + ibuprofen) isn't missed just because ibuprofen's own entry has no interaction data listed.

**Agent 3 — Medical Knowledge Retrieval Agent**
Uses the LLM to read the Agent 1 summary and extract which medical conditions it actually points to (e.g. "hypothyroidism", "iron deficiency anemia") rather than relying on a fixed list of conditions. Fetches background on those specific conditions from the MedlinePlus API, embeds and caches it in Chroma, and retrieves the passages most relevant to this report.

**Agent 4 — Patient Explanation Agent**
Combines the summary, drug interaction findings (including any cross-mention warnings), and retrieved medical background into one warm, plain-language explanation for the patient. Explicitly instructed not to introduce new diagnoses, recommend specific medications or doses, or suggest diet/exercise plans — and never to imply a medication is safe just because no interaction data was found. Always ends with a disclaimer.

## Tech stack

**Backend:** FastAPI, PostgreSQL, JWT auth (signup/login), ChromaDB (vector store), sentence-transformers (embeddings), pypdf (PDF text extraction), httpx (external API calls)

**Frontend:** React (Vite)

**LLM provider:** NVIDIA's [build.nvidia.com](https://build.nvidia.com) free API (OpenAI-compatible endpoint), currently using `openai/gpt-oss-20b` with `reasoning_effort="low"`

**External data sources:**
- [RxNorm](https://lhncbc.nlm.nih.gov/RxNav/APIs/RxNormAPIs.html) — drug name normalization
- [openFDA](https://open.fda.gov/apis/drug/label/) — drug label / interaction data
- [MedlinePlus](https://medlineplus.gov/webservices.html) — consumer health topic background

## Setup

### Prerequisites
- Python 3.11+
- Node.js (for the frontend)
- PostgreSQL
- A free NVIDIA API key from [build.nvidia.com](https://build.nvidia.com) (click any model → **Get API Key**)

### Backend

```bash
cd backend
python -m venv venv
venv\Scripts\activate        # Windows
# source venv/bin/activate   # macOS/Linux

pip install -r requirements.txt
```

Create `backend/.env` (copy `.env.example`) and fill in:

```
DATABASE_URL=postgresql://<user>:<password>@localhost/<dbname>
NVIDIA_API_KEY=nvapi-your-own-key-here
```

> Each teammate needs their **own** NVIDIA API key — keys are not shared, and `.env` is gitignored.

Run the server:

```bash
uvicorn main:app --reload
```

Backend runs at `http://localhost:8000`. Interactive API docs at `http://localhost:8000/docs`.

### Frontend

```bash
cd frontend
npm install
npm run dev
```

Frontend runs at `http://localhost:5173`.

## Usage

1. Open `http://localhost:5173`, acknowledge the disclaimer, sign up or log in.
2. Upload a PDF medical report. Optionally list current medications, comma-separated (e.g. `warfarin,ibuprofen`).
3. Click **Upload & Analyze**. A full run (summarization, drug check, knowledge retrieval, explanation) typically takes under a minute.
4. Review the summary and final explanation, each shown with its disclaimer.

## A note on the LLM provider

This project has switched LLM models twice during development, both times because NVIDIA's free-tier `build.nvidia.com` endpoint for the previously chosen model was retired with no advance warning (`nvidia/llama-3.3-nemotron-super-49b-v1.5`, then `nvidia/nemotron-3-super-120b-a12b`, both reached end-of-life mid-project). The current model is `openai/gpt-oss-20b`, chosen in part because its free endpoint showed significantly higher recent usage, as a rough signal of being less likely to be cut soon.

The model name is intentionally isolated to a single `MODEL` (or `_MODEL`) variable at the top of `summarizer.py`, `explanation_agent.py`, and `medical_retrieval.py`. **If the current model is ever retired, check build.nvidia.com for a replacement, update those three lines, and verify the new model's prompt-following behavior** (reasoning output leaking into responses, markdown formatting despite instructions, etc. have both been issues with different models here) before relying on it for a demo.

---

## Known limitations

- **Synthetic data only.** No real patient data has been used or should be used.
- **Free-tier dependency.** The LLM provider's free tier has shown both rate limits and sudden model retirements; a busy-service error can occasionally surface to the user as a failed request.
- **MedlinePlus lookups** can occasionally fail due to transient network issues; the pipeline continues without that background context rather than failing the whole request.
- **Not a diagnostic tool.** All four agents are explicitly instructed to avoid introducing new diagnoses or treatment recommendations beyond what's stated in the source report.
